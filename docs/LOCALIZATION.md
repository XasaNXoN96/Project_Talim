# Локализация (День 7): узбекский, русский, английский

## Как устроено
Стандартная интернационализация Django: `gettext` в коде, `{% translate %}`/`{% blocktranslate %}` в шаблонах, каталоги в `backend/locale/{uz,ru,en}/LC_MESSAGES/django.po`, **скомпилированные `.mo` лежат в репозитории** (тест сверяет их с `.po`).
- **Исходный язык идентификаторов сообщений — узбекский.** Каталог `uz` содержит те же строки (без пустых); `ru` и `en` — переводы. Fallback-механизм не используется для сокрытия пропусков: тест требует, чтобы в каждом каталоге не было ни пустых, ни `fuzzy`, ни непереведённых (скопированных) строк.
- **Выбор языка:** кнопки `UZ / RU / EN` на всех страницах (портал, публичный сайт, вход, восстановление пароля). Одна POST-форма на **единственный** адрес `/i18n/setlang/` (стандартное представление Django, CSRF, `next` проверяется — внешние адреса игнорируются). Дублирующих адресов по языкам нет. Работает без JavaScript, CSP не менялась.
- **Сохранение:** cookie `django_language` (1 год, `SameSite=Lax`, `HttpOnly`; в production — `__Host-django_language`, `Secure`); для вошедшего пользователя выбор дополнительно пишется в `User.locale`, поэтому следует за ним в другой браузер (если в браузере нет cookie). Порядок: cookie → язык учётной записи → `Accept-Language` браузера → `uz`. Допускаются только три языка (иное значение игнорируется и не пишется в cookie).
- **Текущая страница и фильтры** сохраняются (`next` = полный адрес с параметрами). Пользователь с обязательной сменой пароля может переключать язык.
- **HTML:** `<html lang="…">` и заголовок `Content-Language` отражают активный язык.
- **Письма** (приглашение, уведомления безопасности, восстановление пароля, копии уведомлений) пишутся **на языке получателя** (`User.locale`), а не отправителя.
- **Админка Django:** встроенные тексты — каталоги Django (uz/ru/en есть); названия наших моделей и разделов переведены; названия прав в выпадающих списках показываются на активном языке (`permission_label`).
- **Не меняется:** коды и значения в БД (статусы, виды событий аудита, коды ролей), имена технических заголовков, имена файлов отчётов (`hisobot-ГГГГММДД-ЧЧММ`), права доступа, бизнес-логика.

## Что остаётся неполным или не переводится (честный список)
1. **Переводы выполнены автором кода (ИИ), не носителями языка.** Русский и английский стоит вычитать носителям; особенно узбекский исходный текст и официальные формулировки. Исправления вносятся в `.po`, затем `compilemessages` (см. ниже).
2. **Данные, введённые людьми, не переводятся:** заголовки и тексты новостей, названия подразделений, должностей, учреждений, заданий, документов, комментарии, описания. Исключение — **5 стандартных категорий документов** (хранятся по-узбекски, показываются переведёнными); категории, добавленные администратором, показываются как набраны.
3. **Элементы, которыми управляет браузер,** показываются на языке браузера, а не сайта: выбор даты («mm/dd/yyyy»), кнопка выбора файла («Choose File»), всплывающие подсказки проверки HTML-форм.
4. **Формат даты** во всех языках одинаков — `дд.мм.гггг` (сознательно: единообразие в отчётах и журнале). Числа и размеры файлов форматирует Django.
5. **Журналы приложения и поле `meta` в аудите** — технические, на английском/кодами (не интерфейс).
6. **Название приложения в приложении-аутентификаторе** (`Mirzacho‘l XTB`, настройка `TWO_FACTOR_ISSUER`) не переводится.
7. **Статический макет в корне репозитория** (GitHub Pages) не менялся и не локализовался: это отдельный визуальный эталон со своим JS.
8. Множественные числа (`ngettext`) не используются — в интерфейсе нет строк, зависящих от количества.
9. Админка Django: названия, которые Django берёт из своих каталогов, переведены настолько, насколько это сделано в самом Django; права и модели проекта — переведены нами. Тексты записей в «истории изменений» админки формируются Django.

## Как добавлять и править строки
```bash
cd backend
python manage.py makemessages -l uz -l ru -l en -e html,txt,py --no-wrap --no-location \
  --ignore ".venv/*" --ignore "staticfiles/*" --ignore "private_media/*" --ignore "*/tests*" --ignore "*/migrations/*"
# заполните пустые msgstr в locale/ru и locale/en (в uz — тот же текст, что msgid); уберите пометки «fuzzy»
python manage.py compilemessages --locale uz --locale ru --locale en --ignore ".venv/*"
python manage.py test apps.core.tests_i18n          # каталоги полные, плейсхолдеры совпадают, .mo свежие
```
Правила: в коде на уровне импорта/классов (модели, формы, константы) — `gettext_lazy`, внутри функций запроса — `gettext`; строки с переменными — только через `%(имя)s`, а не f-строки; пользовательские данные в перевод не передавать; технические коды не переводить.
