# Реестр функций варианта C и очерёдность реализации

**Статус:** предложение этапа 0 · **Основа:** HEAD `2894e5c` (24 страницы макета) · **Стек:** [STACK_DECISION.md](STACK_DECISION.md) · **Роли:** [ROLES_PERMISSIONS.md](ROLES_PERMISSIONS.md) · **Данные:** [DATA_MODEL.md](DATA_MODEL.md) · **Оценки:** [BUDGET_AND_ESTIMATES.md](BUDGET_AND_ESTIMATES.md)

Реестр составлен по реальному коду макета: страницы, формы, модальные окна, 13 видов действий с пометкой «Maket» (19 кнопок) и элементы, которые выглядят рабочими, но не подключены.

## 0. Условные обозначения

**Статус в макете**
| Метка | Значение |
|---|---|
| **UI** | Интерфейс нарисован, данные — заглушки (`data.js`, статическая разметка) |
| **UI+JS** | Работает только в браузере на заглушках (фильтры, вкладки, окна, лайтбокс, чат в памяти страницы) |
| **Maket** | Кнопка показывает уведомление «Maket: … ishlamaydi» и ничего не делает |
| **Немой** | Элемент выглядит рабочим, но не подключён (поле поиска, выпадающие фильтры, меню «⋯») |
| **Нет** | Функция нужна для работы, но экрана в макете нет — придётся спроектировать в том же стиле |

**Роли:** Г — гость, С — сотрудник, Р — руководитель подразделения, К — контент-менеджер, HR — кадровик, А — администратор, ТА — технический администратор.
**Этапы:** E1…E13 — основные; E14 — отложенные (см. раздел 3).

## 2. Этапы реализации

Принципы: сначала фундамент, база, безопасность и вход; затем публичный сайт, затем внутренние разделы; чат, геолокация и OneID — только когда они действительно нужны. Каждый этап завершается проверяемым результатом.
Часы — совместная работа вас и Claude, **диапазон «хорошо — с запасом»** (см. допущения в [BUDGET_AND_ESTIMATES.md](BUDGET_AND_ESTIMATES.md)).

## 4. Релизные вехи

| Веха | Состав | Условия запуска |
