# Роли и права доступа

Предложение для согласования. Роли соответствуют разделам, уже нарисованным в интерфейсе (сайдбар портала, кнопки «Xodim qo‘shish», «Topshiriq yaratish», «Yangi yangilik» и др.).

## 1. Роли

| Роль | Кто | Основные возможности |
|---|---|---|
| **Гость** | Любой посетитель | Публичный сайт: новости, педагоги, медиа, структура, открытые документы |
| **Сотрудник** | Работник отдела | Портал: свои задания, документы своего уровня, уведомления, чат, отметка прихода, свой профиль |
| **Руководитель подразделения** | Начальник отдела | Всё как у сотрудника + создание заданий и контроль в своём подразделении, отчёты подразделения, согласование |
| **Контент-менеджер** | Пресс-служба, методист | Создание и правка новостей, фото, видео, профилей педагогов; публикация — по настройке (сразу или после согласования) |
| **Кадровик (HR)** | Отдел кадров | Управление сотрудниками, подразделениями, сертификатами, отчёты по посещаемости, доступ к контактным данным |
| **Администратор** | Руководство / IT | Всё по организации: пользователи, роли, справочники, настройки, отчёты, журнал аудита |
| **Системный администратор** | IT-специалист | Техническое: резервные копии, настройки безопасности, интеграции. Не обязан видеть персональные данные сотрудников |

Принцип: **минимум необходимых прав**. Роли суммируются (например, сотрудник + контент-менеджер).

## 2. Область действия (scope)

| Значение | Смысл |
|---|---|
| `own` | Только собственные записи |
| `department` | Записи своего подразделения |
| `all` | Вся организация |

| Структура, учреждения | Ч | Ч | Ч | Ч | Ч С Р | Ч С Р У |
| Документы публичные | Ч | Ч | Ч | Ч | Ч | Ч С Р У |
| Документы внутренние | — | Ч (по видимости) | Ч С Р (department) | — | Ч С Р | Ч С Р У |

| Сотрудники: контакты и личные данные | — | своё | Ч (department) | — | Ч (all) | Ч (all) |

Права реализуются кодами (`news.publish`, `tasks.create`, `employees.read_contacts`, …). Матрица выше — отправная точка; финальную фиксируем после ответов на вопросы 6 и 8 из [ARCHITECTURE.md](ARCHITECTURE.md).

## 4. Правила

1. **Проверка на сервере.** Скрытие кнопок в интерфейсе — удобство, а не защита. Каждый запрос API проверяет право и область.
2. **Защита от подмены идентификатора (IDOR).** Запрос чужого `id` без права возвращает «не найдено».
3. **Персональные данные:** выдача только при праве, чтение карточки пишется в аудит.
4. **Публикация:** материал виден гостям только в статусе `published` и, где нужно, с подтверждённым согласием на изображения.
5. **Администраторы:** обязательная 2FA, отдельные учётные записи (не общая «admin»), срок жизни сессии короче.
6. **Отзыв доступа:** блокировка пользователя немедленно завершает его сессии.
7. **Тесты:** автоматическая проверка «каждая роль × каждый ресурс × действие» — обязательная часть CI.
