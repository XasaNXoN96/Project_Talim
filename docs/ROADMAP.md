## 1. Как перейти от текущего кода к production

### 1.1 Что делаем с текущим репозиторием
1. Помечаем текущее состояние тегом `design-v1` — это утверждённый дизайн-эталон.
2. Демо на GitHub Pages продолжает работать из текущей ветки, пока production не заменит его.
3. Production-код создаётся **рядом**, в структуре монорепозитория:
```
apps/web        # Next.js: публичный сайт + портал
apps/api        # NestJS: API, WebSocket, фоновые задачи
packages/ui     # компоненты и токены, вынесенные из styles.css
packages/config # общие настройки линтера, TypeScript
docs/           # документация (этот каталог переезжает как есть)
design-v1/      # эталон: текущие HTML-страницы (для сверки внешнего вида)
```
4. Каждая страница переносится по одной: верстка из `design-v1/` → компонент → подключение к API. Внешний вид сверяется автоматически скриншотами (те же ширины 360–1440 px, что мы проверяли вручную).

### 1.2 Что куда переносится
| Сейчас | В production |
|---|---|
| `assets/css/styles.css` (переменные) | `packages/ui`: токены без изменений |
| Компоненты в CSS (`.btn`, `.card`, `.t`, `.badge`, `.tabs`, `.modal`, …) | React-компоненты с теми же стилями |
| `app.js`: сборка шапки/подвала/сайдбара/топбара | React-раскладки `(public)` и `(portal)` |
| `app.js`: i18n-словарь, `t(key)` | `next-intl`/`i18next`, те же ключи |
| `app.js`: иконки | пакет иконок |
| `pages.js`: фильтры, вкладки, пустые состояния | серверные запросы с пагинацией + те же компоненты состояний |
| `data.js` | уходит; его форма → контракты API |
| Имитационный вход | удаляется; `auth`-модуль |
| 15 кнопок «Maket» | пункты бэклога с критериями приёмки |
| Google Fonts | собственный хостинг шрифта |

## 3. Расходы

### 3.1 Разработка

Трудозатраты в человеко-месяцах (ЧМ = ЧН / 4,33), с запасом 25 % на неопределённость:

| Вариант | ЧН | ЧМ | ЧМ с запасом |
|---|---|---|---|
| A | 43 | ~10 | ~12 |
| B | 70 | ~16 | ~20 |
| C | 106 | ~24,5 | ~31 |

Стоимость зависит от того, **кто делает работу**. Ставка человеко-месяца — допущение; подставьте реальную:

| Сценарий ставки (допущение) | A | B | C |
|---|---|---|---|
| Низкая — $2 000 / ЧМ | ~$24 тыс. | ~$40 тыс. | ~$62 тыс. |
| Средняя — $3 500 / ЧМ | ~$42 тыс. | ~$70 тыс. | ~$108 тыс. |
| Высокая — $5 500 / ЧМ | ~$66 тыс. | ~$110 тыс. | ~$170 тыс. |

Если разработку ведёт собственная команда, прямые расходы — зарплаты на срок проекта; подрядчик добавляет свою наценку.

### 3.2 Инфраструктура и эксплуатация (допущения, нужны коммерческие предложения)

| Статья | Оценка |
|---|---|
| Серверы: приложение, БД, хранилище, резервные копии, staging | ~$300–700 / мес |
| Домен, TLS | минимально |
| SMS-провайдер (восстановление паролей, уведомления) | по тарифу оператора, за сообщение |
| Почтовая рассылка | вместе с хостингом или копейки |
| Мониторинг и логи | включены в серверы при self-hosted |
| Тест на проникновение (разово перед запуском) | ~$3 000–10 000 |
| Сопровождение после запуска (исправления, обновления, поддержка) | 15–25 % от стоимости разработки в год или 0,5–1 разработчик |
| Юридическое сопровождение (персональные данные, согласия) | разово, по договору |

Программные лицензии не нужны: рекомендуемый стек полностью открытый.

## 4. Риски

| № | Риск | Вероятность | Влияние | Что делать |
|---|---|---|---|---|
| 1 | **Требования к персональным данным и их размещению в Узбекистане** не учтены | Высокая | Высокое | Юридическая консультация на этапе 0; размещать данные в стране; журнал доступа |
| 2 | **Геолокация сотрудников** признана недопустимой или требует согласий | Средняя | Среднее | Проектировать как опцию; отметка по геозоне, а не трекинг; решать на этапе 0 |
| 3 | **Публикация фото детей и педагогов без согласия** | Средняя | Высокое | Поле согласия обязательно; публикация блокируется без него; процесс получения согласий |
| 4 | **Расплывчатые требования** к заданиям, документообороту, отчётам (макет показывает вид, не процесс) | Высокая | Высокое | Этап 0: интервью с будущими пользователями; согласование потоков до разработки |
| 5 | **Разрастание объёма** (чат, интеграции, «ещё один раздел») | Высокая | Среднее | Варианты A/B/C; изменения — через оценку и согласование |
| 6 | **Утечка данных / взлом** (загрузка файлов, XSS, подмена идентификатора) | Средняя | Высокое | Практики из ARCHITECTURE §3.4; тесты прав в CI; тест на проникновение; обновления |
| 7 | **Нет данных или структуры для переноса** из существующих систем | Средняя | Среднее | Выяснить на этапе 0; импорт из таблиц как запасной вариант |
| 8 | **Зависимость от одного разработчика** | Средняя | Высокое | Документация, ревью кода, вторая пара глаз на ключевых модулях |
| 9 | **Контент не будет наполняться** (сайт есть, новостей нет) | Средняя | Среднее | Назначить ответственных, обучить, простой редактор, процесс согласования |
| 10 | **Задержка согласований** (решения по хостингу, домену, государственным требованиям) | Средняя | Среднее | Начать согласования параллельно с этапом 0 |
| 11 | **Слабый интернет у пользователей** | Средняя | Среднее | Бюджеты размера страниц, оптимизация изображений, SSR |
| 12 | **Требования к государственным интернет-ресурсам** (сертификация, аудит) | Неизвестна | Неизвестно | **[Выяснить перечень требований и порядок прохождения]** |
| 13 | **Перевод на ru/en не готов к запуску** | Высокая | Низкое | Запуск на uz; i18n уже заложена; добавлять языки позже |
| 14 | **Дизайн «ломается» на реальном контенте** (длинные заголовки, нет фото) | Средняя | Низкое | Состояния уже проработаны в макете; скриншот-тесты на реальных данных |

## 5. Критерии завершения этапов

| Этап | Готово, когда |
|---|---|
| 0 | Подписан объём первой версии; ответы на 10 вопросов; решение по хостингу и юридическим вопросам |
| 1 | Вход с 2FA работает; роли и права проверяются тестами; CI зелёный; staging доступен команде |
| 2 | Редактор публикует новость; страница педагога не публикуется без согласия; Lighthouse ≥ 90 по скорости и доступности на ключевых страницах |
| 3 | Руководитель ставит задание, исполнитель закрывает, история сохраняется; пользователь видит только положенное |
| 4 | Отметка в пределах геозоны фиксируется; чат доставляет сообщения; отчёт выгружается |
| 5 | Нет открытых критических и высоких уязвимостей; восстановление из копии проверено; пользователи обучены |
