## 4. Действия владельца инфраструктуры (короткий список для начала реального staging)
1. Выдать отдельную ВМ (Ubuntu 24.04, ≥ 2 vCPU, 4 ГБ, 40 ГБ + место под копии) и SSH/sudo оператору; письменно подтвердить, что это не production и данные только вымышленные.
2. Создать DNS-запись и выпустить доверенный сертификат (или разрешить ACME) для имени staging.
3. Выдать SMTP (хост, порт, STARTTLS, учётная запись) и тестовый ящик, который оператор может прочитать.
4. Разрешить исходящий доступ ВМ к серверам сигнатур ClamAV (`freshclam`).
5. Открыть 80/443 снаружи (SSH — по списку адресов); 8000 и 5432 — только локально.
6. Выдать второе окружение (машина или каталог с PostgreSQL и правом `CREATEDB` для роли копий) и согласовать место внешних копий и способ передачи (решение + доступ только на добавление).
7. Назначить ответственного за сервер, дежурного и канал оповещений; утвердить `INCIDENT_RESPONSE.md`.
8. Определить, кто и где хранит копии ключей и паролей (вне серверов и вне копий данных).
9. Разрешить правило `sudoers` только для `systemctl restart talim-gunicorn` пользователю `talim`.
