# Автоматические напоминания (планировщик)

**Статус: команда готова и безопасна для автоматического запуска, но планировщик на сервере НЕ настроен — напоминания сами не создаются.** Автоматизация считается выполненной только после установки таймера на сервере и проверки (чек-лист ниже).

## Команда
```bash
python manage.py send_task_reminders
```
Создаёт уведомления «срок завтра/сегодня» и «просрочено» для исполнителей **открытых** заданий. Идемпотентна:
- на каждую пару (задание, исполнитель, срок, вид) — не более одного уведомления (уникальный ключ в БД; параллельные запуски упираются в него, лишние тихо пропускаются);
- команда берёт блокировку PostgreSQL (`pg_try_advisory_lock`): если другой запуск ещё работает, второй сразу выходит с сообщением «skipped»;
- «срок скоро» — один раз на срок; «просрочено» — один раз (не каждый день); при смене срока ключ меняется — можно получить новое напоминание;
- границы по **местной дате** (`Asia/Tashkent`), а не по UTC: срок «сегодня» и «завтра» — «скоро», раньше сегодняшнего — «просрочено».

## Установка (рекомендуется systemd timer)
Файлы: `backend/deploy/systemd/talim-reminders.service` и `talim-reminders.timer` (раз в час, `Persistent=true` — пропущенный запуск догоняется после перезагрузки).
```bash
sudo cp backend/deploy/systemd/talim-reminders.* /etc/systemd/system/    # поправьте User, пути, EnvironmentFile
sudo systemctl daemon-reload && sudo systemctl enable --now talim-reminders.timer
systemctl list-timers talim-reminders.timer
sudo systemctl start talim-reminders.service && journalctl -u talim-reminders.service -n 20   # ручной пробный запуск
```
Вместо этого можно использовать cron: `backend/deploy/systemd/crontab.example` (с `flock -n`, чтобы запуски не накладывались).

## Что проверено
- Тесты (`apps/notifications/tests.py`): повторный запуск, границы суток (вчера/сегодня/завтра/послезавтра), смена суток около полуночи по местной дате, «срок скоро» один раз на два дня, смена статуса не вызывает повтор, закрытые задания и неактивные пользователи пропускаются, смена срока даёт новое напоминание.
- Настоящие **параллельные** сессии БД (потоки, `TransactionTestCase`): 8 одновременных вызовов с одним ключом → одна запись; 8 параллельных запусков команды → ровно по одному уведомлению на исполнителя; удерживаемая блокировка → второй запуск пропускается.
- **Не проверено:** фактическая работа systemd/cron на сервере; работа при нескольких серверах приложения (блокировка и ключ работают через общую БД, но это не тестировалось на нескольких узлах).

## Чек-лист включения
- [ ] Таймер установлен и активен (`systemctl list-timers`).
- [ ] Пробный запуск вручную прошёл без ошибок.
- [ ] Через час в `journalctl` видна строка `due_soon=… overdue=…`.
- [ ] Настроено оповещение, если юнит завершился с ошибкой (`OnFailure=` или мониторинг).
