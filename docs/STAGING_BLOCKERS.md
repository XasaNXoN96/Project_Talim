# Блокеры настоящего staging (День 23)

**Состояние:** настоящего staging **нет**: нет сервера, домена, сертификата, SMTP, доступа к сигнатурам ClamAV, разрешения владельца инфраструктуры. Ни одна инфраструктурная проверка не выполнялась и не имитировалась. Этот документ отделяет **свойства кода, подтверждённые тестами и репетициями в песочнице**, от **требований к инфраструктуре, которые не проверены**, и для каждого блокера называет ресурс, ответственного (роль, не имя), критерий снятия и команду проверки. Блокер снимается только записью (дата, кто, результат) вне Git после выполнения команды **на сервере**.

«Ответственный» — роль: **ВИ** — владелец инфраструктуры (хостинг, DNS, сеть); **З** — заказчик (решения, назначения); **ОС** — ответственный за сервер (оператор); **Ю** — юрист заказчика.

## 3. Что подтверждено тестами и репетициями (свойства кода) — **не** инфраструктура

* Права runtime-роли (нет суперпользователя, нет DDL, журнал аудита только добавляется) — `deploy/postgres/verify_roles.sh`.
* Топология из **трёх ролей** (владелец / runtime / копии): резервная копия от роли копий, проверка восстановления в отдельной БД с её же правами, роль без `CREATEDB` падает с понятной ошибкой, восстановление поверх рабочей БД отказано, рабочая БД не тронута — `deploy/backup/verify_backup_roles.sh` (**найден и исправлен дефект:** прикладные шаги проверки восстановления шли от runtime-роли, у которой нет прав на временную БД).

## 5. Защита от случайного восстановления поверх рабочей БД
* `restore_check.sh` **никогда** не работает с рабочей БД: имя временной БД должно содержать `restore`/`scratch`/`check`, не может совпадать с `DB_NAME`/`PGDATABASE` (код 2, проверено `verify_backup_roles.sh`), каталог файлов должен быть пустым; временные данные удаляются при выходе.
* Настоящее восстановление после аварии автоматикой **не выполняется** (только описано в `BACKUP_AND_RESTORE.md`): остановить приложение, восстановить в **чистую** БД и каталог, `migrate`, `apply_grants.sql`, `verify_document_files`, `check_scanner --eicar`, вернуть `talim.env` с **теми же** `OTP_ENCRYPTION_KEYS`. Потеря данных после точки копии неизбежна и объявляется заранее.
